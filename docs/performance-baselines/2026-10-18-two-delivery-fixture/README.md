# Controlled two-delivery fixture · hosted reproducibility check · 2026-10-18

[Workflow run 39174417864](https://github.com/swyxio/TeslaRoadster6/actions/runs/39174417864) compared clean 0.0.32-alpha builds of base `1f722ddc8fe9e2950b2af8d866691d78af49bf4a` and candidate `4d7cee443765042d0c2fcb576372e771e1d308a3`. The revisions differ in playtest tooling and documentation, not the game runtime. This is a same-game fixture reproducibility check, not a game-performance comparison or budget.

Both runs completed two pickups and drop-offs, two upward jumps, landings and sustained forward-powered flight. The fixture deliberately staged the second order after the first delivery; it does not test natural second-job selection. The five sampled paths aligned, with 0.678 m p95 and 3.408 m maximum separation. Both browser manifests report zero page and console errors and no video. The staging commands took 207 ms base and 131 ms candidate, as recorded in the original manifests; the historical reports predate the separate duration field. Frame p95 includes this mostly stationary period, and distance-based route matching does not control elapsed time.

The hosted three-CPU Apple M1 virtual runner used Chromium and an ANGLE paravirtual Metal renderer. Its one-minute load averages were 9.87 → 14.85 for the base and 16.55 → 12.66 for the candidate. Browser callback p95 was 116.7 ms for each; one-room simulated/wall ratios were 0.914 and 0.918. These single, heavily loaded observations are descriptive, not GPU-completion, physical-device, production-capacity or regression evidence. See [comparison.md](comparison.md) and the [original workflow summary](summary-original.md.gz).

Each side retains its report, browser manifest, trajectory and input events, plus both synthetic motion outputs and traces. [scenario.json](scenario.json) is extracted from the candidate revision and matches the scenario SHA-256 in both reports. Compressed files were decompressed and compared byte-for-byte with the hosted artifacts. [UNCOMPRESSED-SHA256SUMS](UNCOMPRESSED-SHA256SUMS) records the uncompressed payload hash for each named gzip file. The retained JSON and Markdown were screened for common credential patterns and nonempty credential fields; none were found. Run `shasum -a 256 -c SHA256SUMS` here to verify the archive.
